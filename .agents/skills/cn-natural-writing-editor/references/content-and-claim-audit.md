# 内容与判断审查

用途：检查“很顺但没有新信息”、证据不足和结论过强的问题。优先级高于换词。

适用模式：`prewrite`、`diagnose`、`rewrite`、`cold-read`。

## 逐节检查

对每个主要段落记录：

- 这一节增加了什么新信息；
- 具体对象、动作、时间、结果或后果是什么；
- 是否解释了为什么，而不是只列出是什么；
- 是否存在案例、失败条件、反例、取舍或责任主体；
- 作者是否做出一个可以被不同意的判断；
- 判断的确定性是否超过材料支持的范围；
- 这一节是否只是重复前文。
- 具体细节是功能性事实（谁、多久、结果、成本、意外），还是只为氛围服务？

一节如果只有“重要、复杂、值得关注、需要协同、发挥优势、规避风险”等结论，没有对象、机制或条件，标记为 `FOUND`，优先要求补材料或删减。

## 事实与来源

对数字、日期、引用和专业断言逐项询问：

1. 来源是否真实存在？
2. 来源是否支持正文这句话，而不只是支持相邻的较弱判断？
3. 数字有没有样本、分母、日期、单位和统计口径？
4. 时间、地点、人物和因果关系是否互相一致？
5. “相关、可能、观察到”是否被改成了“导致、证明、一定”？
6. 术语是否有定义，概念层级是否稳定？

只有文章和来源原文都提供时，才标记 `CLEAR`。仅凭模型记忆、搜索摘要或文章内部自引不能完成核验；缺来源时标记 `UNKNOWN`。

## 判断、机制和边界

把文章的中心判断写成：

```text
在什么条件下，对什么对象，我主张什么，因为哪些材料；
这个判断不适用于什么情况，什么证据可能推翻它。
```

检查文章是否把个人经历扩大成普遍规律，是否把建议写成事实，是否避开了所有责任和取舍。个人实践可以支持“我在这个场景中这样做有效”，不能直接支持“所有人都应该这样做”。

额外检查：

- 作者是否给自己的结论留了后路？是否把“可能、观察到、相关”写成“导致、证明、一定”？
- 是否所有争议都停在“各有利弊”？是否避开了责任和取舍？
- 责任是否落到具体的人，还是被分散给团队、体系、流程？

如果材料不足，不补写“某企业”“某用户”或虚构案例；提出最多 3–6 个能改变判断的问题，或保留 `UNKNOWN`。

## 输出格式

```markdown
### 内容审查

中心判断：
证据状态：CLEAR / UNKNOWN

高优先级问题：
- 位置：
- 问题：
- 需要的材料或核验：
- 安全处理：补充、降低语气、删减或保留未知

不应修改：
- 事实、原话、术语或作者判断
```

不要把内容审查结果压缩成“信息密度较低”一句话。指出缺失的对象、动作、机制、证据或边界。
