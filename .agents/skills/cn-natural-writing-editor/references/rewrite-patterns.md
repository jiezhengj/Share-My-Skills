# 改写动作参考

先改信息和结构，最后改语言。以下示例只说明方向，不是固定模板。

## 把抽象评价改成观察

```text
原：这个方案显著提升了效率。
改：原来每次都要手动确认的步骤，现在可以在一次检查中完成；但异常情况仍然需要人工处理。
```

保留实际结果和限制，不要凭空增加百分比。

## 把泛泛建议改成条件化建议

```text
原：团队应该加强协作。
改：如果问题出在交接信息不完整，先把输入、负责人和完成标准写在同一个地方，比增加会议次数更直接。
```

只有在作者确实提供了这种判断或材料时才能这样改。

## 把三点清单改成过程

```text
原：要明确目标、完善流程、加强反馈。
改：先把目标写成可观察的结果，再让执行者按同一份结果检查；如果结果不清楚，后面的反馈只会变成意见堆积。
```

不要机械删除所有列表。列表适合并列事实、步骤和检查项；不适合承载没有差异的三个抽象名词。

## 处理对称句

检查“不是……而是……”“不仅……更是……”“从……到……”是否真的承担逻辑。如果只是制造气势，拆成具体主语和动作；如果确实需要对比，保留并补足两边的差异。

## 处理低信息量叙述过渡

检查“但我没有……而是……”“我没有马上……而是……”这类句子是否只是先交代“没有立刻做某事”，再用“多问了一句”“先想了想”引出真正内容。如果前半句没有构成有信息的对比，直接写出实际动作、检查或判断：

```text
原：但我没有马上开始执行，而是多问了一句：
改：我准备把这份方案交给 Goal 执行时，先回头检查了一遍：
```

如果下一句本身就是关键问题，可以合并成一个句子，减少作者自述的缓冲层。只有“没有做 A，而是做 B”确实说明了两种方案、责任或取舍的差异时，才保留对比结构。

## 处理回顾渲染与无必要过渡词

回顾性句式（“回头看”“后来才意识到”“这才发现”）只在作者确实经历了认识变化时使用。如果认识一开始就清楚（来自文档、官方来源或前置知识），直接陈述，不用回顾句式包装——把已知包装成顿悟，是伪造认识弧线，把小事渲染成大事。

无必要过渡词（“不过”“其实”“回头来看”“换句话说”）在删掉后逻辑仍清楚时删除。过渡词应该承担真实的转折、因果或递进，不是填充。

## 处理第一人称叙述支架

不要把所有“我”都删掉。先问：这个“我”是否提供了作者做过的动作、亲自看到的结果、当时的判断，或信息来源？如果没有，只是引导下一句话，可以直接写出判断或事件：

```text
原：我先想到的是范围问题。
改：第一处问题出在范围上。

原：我觉得最容易被忽略的是 UNKNOWN。
改：最容易被忽略的，反而是 UNKNOWN。

原：我现在会怎样写一个 Goal？
改：真要把一个 Goal 交给 Agent，可以先写这些。
```

如果删除“我”会抹掉作者的实际行动、观察或责任，就保留它。目标是减少报幕感，不是把个人复盘改成无主语的技术文档。

## 处理备忘录化句子

无主语句子、中立“会”陈述、自说自话过渡，根源是作者心里没有假想读者。修复不是删字、补字，而是重写句子，让它对读者说话：

- 心里想“读者此刻会怎么想”，用“大家”“我们”“你”“如果你也”把读者拉进来；
- 句子没有明确主体时，重构句子，而不是补一个生硬的主语；
- 删除不承担读者功能的过渡，或换成对读者说的衔接；
- 只处理备忘录式“我会”陈述（主语是“我”、未来行动，自说自话）——改成对读者说的指向或直接陈述；不要动客观机制/规律的“会”（主语是事物，如“Agent 会一直工作”“每个决定都会转化”），它们描述运行方式，是正常的。

## 处理开头

优先从一个真实问题、动作、冲突或反常结果进入。不要在没有材料时写“在当今时代”“随着……不断发展”。

进入前先确认核心概念对读者可理解。标题或开头第一个动作用到的术语，读者第一次遇到时能否理解？必要时先用一句白话定义锚住（如“Goal 是 Agent 框架里，把一个长任务拆成有明确范围、验收和结束条件的小交付，达标就停”），再进入具体故事。“从具体进入”不等于“跳过背景直接进入动作”。

处理新概念时，先用目标读者已知的工具、场景锚定，再给定义。不要只给抽象定义。素材里现成的熟悉参照物（如 Codex、Claude Code）优先使用：先写“大家常用的 Codex 和 Claude Code 里就有这个模式”，再解释 Goal 是什么。参照物能拉近距离，抽象定义不能。这条适用于全文，不只是开头。

## 处理结尾

结尾完成文章自己的判断：

- 个人经历停在仍然保留的限制；
- 观点文章停在适用边界或具体取舍；
- 方法文章给出最小下一步；
- 技术文章列出剩余风险或验证要求。

不要为了“完整”增加“未来值得期待”“让我们共同努力”等泛化句。

结尾可以有信息量的点题：把具体案例的判断推进到更大结构（如从“Goal 需要验收契约”推进到“自建 Agent 的事件驱动循环同样需要收敛条件”），但必须有材料依据，读者能看到推导关系。区分空洞金句与有信息量点题的标准：删掉这句读者损失什么？损失一个新判断=有信息量，保留；只损失一句漂亮话=空洞，删除。

## 形态级改写

改写前先识别形态问题（命名密度、金句式升华、否定对仗成串、情绪缺席、氛围性细节，见 `human-narrative-shape.md`），回到作者材料，不补造。

形态问题的解决方式是补功能性事实，不是补氛围。示例只作方向，不是模板：

```text
原：人工智能正在深刻重塑教育生态，为个性化学习带来前所未有的机遇。
改：在这门六十人的编程课中，教师先让模型解释三类常见报错，再由助教复核。基础问题的平均回复时间缩短了，但涉及课程自定义框架时，模型多次引用不存在的接口，因此最后一轮仍必须人工检查。
```

第二段增加了规模、流程、效果、失败条件和责任主体，读者可以判断真假，也能看出作者的观察和取舍。材料不足时标记 `UNKNOWN`，不补写。

## 禁止动作

- 添加错别字、随机口语和虚假停顿；
- 添加作者没有说过的原话；
- 用同义词批量替换制造“去 AI”假象；
- 把技术文章强行改成聊天体；
- 把不确定性改成确定性；
- 为每个小节补一个总结句；
- 为降低 AI 味添加“盯着屏幕”“深夜”“反复”等氛围性细节；
- 自报情绪（“我当时很烦躁”），而不是通过选词、节奏和处境承载；
- 把成稿改造成对话腔（口语、第二人称、未展开指涉、句法粗糙）。
