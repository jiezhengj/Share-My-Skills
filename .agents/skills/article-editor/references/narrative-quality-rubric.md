# 叙述质量与 AI 化表达诊断表

当用户说文章有 AI 味儿、可读性差、故事性弱、不像人在说话、过度抽象，或明明是个人文章却像说明书时，读取这份参考资料。

## 先判断目标文体

不要把所有文章都强行写成故事。

- **技术文档**：直接、条件明确、步骤可检查是首要标准。不要为了让它“像人”而添加个人场景。
- **个人文章或经历文**：读者应该能跟上发生了什么、作者看到了什么、什么发生了变化，以及哪些内容可以迁移。
- **文章与方法的混合文体**：具体经历应当生长出方法；方法在结尾前应当回到经历或判断变化。

## 核心区别

“像 AI”不等于正式、语法完整、句子长或缺少口语词。应从推理和叙述表面诊断：

- **叙述链**：处境或张力 → 行动或选择 → 后果 → 判断变化 → 可迁移含义；
- **作者在场感**：作者在观察、怀疑、决定、比较、回忆或修正看法，而不只是宣布结论；
- **读者路径**：读者知道问题为什么与自己有关，也知道下一节为什么接着上一节出现；
- **抽象密度**：抽象名词和评价没有持续替代行动者、动作、场景、证据或后果；
- **文体稳定性**：混合文体在从个人经历转向一般建议、再转回来时，给读者清楚提示。

作者在场感不等于反复使用“我”。第一人称承担证据、观察、判断或责任时应保留；只是在宣布顺序或引出泛泛结论时，可以删除或合并。

## 人的判断与模型化表达

诊断 AI 化表达时，先看思维和叙述是否被压平，而不是先改口语。活人的文章往往保留：当时为什么觉得某种理解合理，什么行动或事实暴露了阻碍，为什么做出下一步选择，结果怎样改变判断，以及哪些地方仍然不能确定。模型化表达容易把这些压缩成“结论—问题—方法”，把每一步都写成进展，把不断发现问题写成不断完善，把未解决部分整理成完整的总结。

这条检查适用于个人经历、项目复盘、方法文章和解释型文章。它不要求虚构故事，也不要求使用对白或大量第一人称；可以通过前提、阻碍、取舍、后果和边界完成。纯技术文档仍以可查找、可执行为先，不因缺少认识过程而被判为 AI 化。

读者视角不是添加“读者可能会问”的模板句，而是判断读者此刻会怎样理解、什么事实会打破这种理解、下一段应回答哪个疑问。只有在真实存在阅读阻力时，才使用读者代理。

## 项目经历的履历化与报告化

个人项目复盘容易被整理成“项目背景 → 第一轮 → 第二轮 → 成果”的履历报告。它可能事实完整、时间线正确、句子流畅，却仍然缺少作者在场感。识别时检查以下组合，而不是单独检查“第一轮”或其他阶段词：

- 连续多个段落只写阶段状态、执行动作和归纳成果，没有独特的对象、动作、观察结果或判断变化；
- 具体文件、工具和规则只是材料清单，没有说明它们在什么冲突中发挥了什么作用；
- 第一人称只负责报幕“我接手、我选择、我先、我让、我和”，删掉后没有损失事实、观察、判断或责任；
- 每个阶段都被写成合理的进展，读者看不出哪一阶段只是局部完成，哪一阶段真正改变了整体结果；
- 段落可以把项目名、工具名和对象名替换掉，移植到另一个项目仍然成立。

这类问题不是靠增加对白、口语词或更多“我”来修复。优先为每个主要阶段保留一个作者原始材料中明确的对象、动作、结果或判断；材料没有提供时，压缩该阶段、标记 `UNKNOWN` 或回到访谈，不得用抽象总结补齐。

### 作者原话与模型新增概括的区分

专业术语、概念词、比喻和不完全口语化的表达，只要来自作者原始材料，就不能因为“听起来像模型”而被判为 AI 痕迹或擅自替换。先标记来源权限，再判断它在段落中是否被解释、是否承担了真实判断。需要修复的是未经来源支持的模型新增概括、事实漂移和过度顺滑的编排，不是作者自己的词。

## 素材权限与编织方式

让每种材料的来源权限保持可见：

| 材料 | 可以安全使用的方式 | 不允许的跳跃 |
| --- | --- | --- |
| 作者原始陈述或明确经历 | 作者明确说过的行动、观察、感受或判断 | 新增场景、对话、感官细节或人物关系 |
| 外部理论或文档 | 定义、机制、公共事实或来源中的论点 | 写成作者亲自知道、使用或经历过的内容 |
| 假设示例 | 明确标记为假设性的说明 | 写成真实用户、朋友、工作场景或观察结果 |
| 作者推断 | 以观察或推断的强度表达 | 加强成因果结论或普遍规律 |

混合文体文章要绘制材料关系，而不是把方法简单排在故事后面：

```text
案例或观察 → 暴露出的问题 → 概念或来源解释问题 → 判断发生变化 → 方法回应读者
```

如果一个概念没有解释案例，或者案例没有改变读者对概念的理解，两者的连接就是装饰性的。应询问补充材料或标记为 `UNKNOWN`，不要编造桥梁。

## 判断轨迹与过程收口

个人经历、项目复盘、方法复盘和其他过程型文章不能只写“做了什么”和“得到什么结论”。应保留一条可复原的判断轨迹：

```text
原本的预期 → 采取的行动 → 观察到的结果 → 局部成功 → 整体是否推进 → 时间或资源成本 → 停止动作 → 判断变化
```

Agent、Goal、Workflow 只是其中一类例子，不是启动这套检查的必要条件。这里有几个容易混淆的地方：

- 某一步做对了，不等于整体状态改善；
- 找到新的冲突，不等于需求、文章或项目质量提高；
- 改了很多内容，不等于原来的结构性问题被解决；
- 没有明显错误，不等于出现了结束条件；
- 每一轮都有局部理由，不等于整个过程值得继续。

如果过程出现“每次检查都能找到一个看似合理的新问题”，应追问三件事：为什么当时继续是合理的，什么时候看出整体没有推进，最后由什么动作停止或转向。还要写明时间、Token、沟通或返工成本；材料没有提供数字时不要擅自补数字。停止后仍不清楚的内容保留为 `UNKNOWN`，不要用完整的总结替代它。

## 常见模式与修复方向

| 模式 | 表现 | 修复方向 |
| --- | --- | --- |
| 规则先行的开头 | 读者还没看到问题，文章就开始“所以”“应该”“重点是” | 先放处境、张力或失败尝试，再从中推出规则 |
| 薄弱的故事 | 只说发生过某件事，省略关键动作或后果 | 补回谁做了什么、看到了什么、说了什么、原本期待什么，以及什么改变了 |
| 只有总结的反思 | 只说“后来发现确实如此”，省略让结论变得必要的判断冲突或执行瞬间 | 补出具体行动、阻碍、后果和判断变化 |
| 清单式推进 | 每节都重复“抽象判断 → 清单 → 模板” | 给每个主要清单补上理由、案例、后果或边界 |
| 泛化的 AI 化表达 | 抽象主语和顺滑过渡很多，可见行动者很少 | 用具体行动者、动作、结果、不确定性或比较替代抽象；不要自动添加口语词 |
| 从案例跳到规则 | 把个人例子当成普遍建议 | 标记哪些是个人实践、观察、推断或建议，并说明迁移边界 |
| 概念贴在案例后面 | 理论出现了，却没有解释案例的转折点 | 找到概念回答的具体问题，再回到案例或判断变化 |
| 读者路径断裂 | 规则清楚，但读者不知道下一节为什么出现 | 补充预期问题、反对意见或后果来连接章节；不要添加填充性对话 |
| 第一人称叙述支架 | 多段以“我首先想到”“我觉得”“我会……”开头，却没有新证据 | 保留真实动作或判断，把转场标签改成直接事件或结论 |
| 局部成功冒充整体进展 | 某一步、单条修订或单个问题都成功，却看不出整体判断或结果改变 | 并列写局部结果和整体结果，补出成本与判断变化 |
| 无限查漏、没有收口依据 | 执行者持续发现新问题，文章只写成“不断完善” | 写明继续的理由、整体不推进的证据、停止或转向动作和剩余未知；不要制造假完成 |
| 项目经历履历化 | 多个阶段按同一套“背景—动作—成果”平铺，工具和文件变成清单，作者判断被阶段标签遮住 | 恢复每个阶段独有的对象、动作、观察或判断变化；没有材料时压缩或标记未知，不用换词和口语填充 |
| 延后的结尾 | 以总结收尾，或承诺下篇再说 | 回到开头的问题，完成判断变化或决定 |
| 概念命名过密 | 自创概念承载结构感（“过程成功/交付成功”“假成功”） | 回到作者原话，判断这些名字是否作者自己的词；是则保留，否则去掉名字直述现象 |
| 金句式升华 | 每节结尾收成格言（区别于“未来展望”） | 区分空洞金句（复述结论、对仗拔高、删掉不损失判断）与有信息量的点题（把具体判断推进到更大结构、有材料依据）；空洞的删除，有信息量的保留 |
| 否定对仗成串 | 全文密集“不是……而是……” | 保留有真实对比的，删除只制造气势的 |
| 情绪缺席 | 失败被立即翻译成冷静判断 | 回到访谈，问处境与后果，不补写情绪词 |
| 氛围性细节 | 细节只为营造氛围，无信息功能 | 替换为功能性事实；没有就标记 `UNKNOWN` |
| 开头锚点缺失 | 第一段直接用核心术语/动作，读者第一次遇到无法理解 | 进入具体问题前，先给核心概念一句白话定义或建立直觉 |
| 概念无参照锚定 | 新术语/概念首次出现只给抽象定义，读者要靠自己经验猜 | 先给目标读者已知的工具/场景锚定（如“大家常用的 Codex、Claude Code 里就有”），再给定义；全文适用 |
| 指向性词悬空 | 时间、空间、关系或回指词暗示了一个不存在的参照（如“问题在别处”，但前文没有对应的“此处”或问题位置） | 让读者能指出它所指的事件、对象、位置或对照；如果只是空转过渡，改写成具体的发生、变化或因果。不要把指向性词本身列为禁词 |
| 回顾渲染 | 用“回头看”“后来才意识到”把已知认识包装成顿悟，作者没有真实认识变化 | 来源明确、一开始清楚的认识直接陈述；回顾句式只在真实认识变化时用 |
| 备忘录化 | 删“我”后无主语句子密集，中立“会”陈述，自说自话过渡，像给自己写的笔记 | 补明确主体或用“我们”拉近距离；删不承担读者功能的过渡；“会”改为面向读者 |

形态类模式的判断依据是本文件前述的概念命名、情绪缺席、氛围性细节和备忘录化等正反例；需要完整边界时读取本技能的 `human-narrative-shape.md` 与 `human-narrative-samples.md`。这些维度是思维形态判断，不要求文章具备对话特征，也不依赖其他技能目录。

## 高价值访谈问题

只询问能够改变文章的问题：

1. 当时原本怎样理解这个问题，什么事实或行动让这种理解遇到阻碍？
2. 在转折点之前期待什么，之后又理解了什么？
3. 关键时刻，具体的行动者做了什么、看到了什么，或者留下了什么没有解决的问题？
4. 哪个细节最能显示旧理解与新理解的差别？
5. 核心结论的哪一部分可以迁移到其他案例，迁移到哪里就应该停止？
6. 哪个来源或概念解释了转折点，如果没有它，什么部分仍然无法解释？
7. 每个阶段原本期待什么、实际做了什么、看到了什么？哪些只是局部成功，整体判断或结果是否推进？
8. 为什么继续或转向一度看起来合理，成本如何累积，最后什么动作让过程停止或改变方向？停止后还剩下什么未知？

## 冷读检查

对个人文章或混合文体，陌生读者应该能够回答：

- 在文章结论之前，究竟发生了什么？
- 作者的看法在哪里发生了变化，为什么变化？
- 为什么方法会从这次经历中自然地生长出来？
- 哪些主张只适用于这个案例，而不是普遍规律？
- 如果文章写的是过程或复盘，读者能否区分“这一阶段做对了”和“整体判断或结果向前了”？
- 读者是否知道过程为什么停止或转向，哪些地方仍然不能据此下结论？
- 读者能否说出每个主要阶段至少一个具体对象、动作、观察结果或判断？
- 如果替换项目名、工具名和对象名，主要段落是否仍然可以原样移植到另一个项目？如果可以，应判为履历化风险。
- 专业术语、概念词和比喻是否确实来自作者或来源材料？不要把作者原话误判为模型新增表达。

如果读者只能复述规则，却无法复原产生规则的事件或推理过程，应诊断为叙述问题，而不只是措辞问题。

## 复盘文体身份与锚定

个人复盘避免写成论文/专栏。合格复盘可含：困惑、未解决、时间锚点、允许不完整；工整对称 + 每节收束 + 无时间锚点 + 句句笃定 = 论文感漂移。

- **入口承诺**：合格复盘从“我为什么做这件事”（具体动机/情绪/麻烦或概念锚点）进入，启发在经历之后浮现；不合格是“主题先置”——开场先透支结论。
- **回指与指向性词锚定**：方法论术语、时间/空间/关系指向词或回指前文事物（“对照组”“旧技能”“别处”）在使用处必须让读者接上三件事——所指（是什么）、参照（相对什么“旧/新”或“此处/别处”）、来历（从哪来、为什么存在）；“旧/新”标签要符合真实时间线（被标“旧”的东西可能其实是“最终调整前的最新状态”）。修复优先最轻锚定；如果词语没有真实参照，直接改写发生了什么，不要靠增加解释从句或把词语换成另一个抽象词来掩盖。
- **过度收束**：每节末尾的收束句是否有新增信息，还是只是复述/升华？每节都收束且无新增信息 = 假完整。
- 形态样本：正向——个人复盘（有困惑、有未解决、有时间锚点、有松弛）；反向——工整论文感（对称、每节收束、自我声明开场、时间锚点缺失、句句笃定）。

## 材料与意图边界

- **查多**：是否添加了没有证据支持的内容。
- **查少**：每个核心论点，读者能否复原至少一个来源明确的关键事实/案例/数字；文中省略了哪些支撑证据。
- **查歪**：是否给作者虚构/夸大了未必有的目标、动机或对立面；素材技术名词不能自动变成作者“目标”；认识时间线是否失真（把“事后才想起、觉得暗合”写成“过程中反复对照”）。
- **查混**：任务元信息（“会话丢失了”“素材在 XX”）属于“对我说的”，默认不写进正文；若确要作为素材，必须先向读者交代清楚发生了什么（谁/什么/何时/为什么）。
