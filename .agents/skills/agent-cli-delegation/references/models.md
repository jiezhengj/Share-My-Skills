# 识别模型与可用性

用户明确指定模型时，解析为准确 provider/model/variant；名称对应多个身份时展示候选及区别，请用户选，不凭近似字符串决定。未指定沿用 CLI 默认或续接会话的有效模型，不主动优化。

本技能不自主按“便宜”“思考能力强”或“根据任务智能选择”代选，也不维护能力/价格对比表或运行时排名。仅有这些偏好时，说明目前不能可靠代选，请用户指定模型；确定前不启动委派，也不把默认模型说成满足偏好。模型目录可用于身份消歧，不能用名称或 thinking 标签证明更便宜、更强或更适合任务。

区分目录可见、已有账号/权限信号与本轮实际调用成功；每层不能代替下一层，认证不代表模型额度。实际身份只取原生事件/session 消息字段，未知为 null，不用请求值或模型自称冒充。不为测试创建账号、provider、配置或付费。

# 故障分类与具体替代授权

先读取原生错误、最终结果、已执行工具和 session 状态。配额错误只说明本次请求；核对完整 provider/model 与既有路由，不推断整个账号余额。

| 故障 | 处理 |
| --- | --- |
| 模型不存在/不可用、模型局部额度或局部限流 | 默认报告并停止换模；有具体候选及顺序授权时才执行该顺序 |
| 认证、账号权限、整体额度、工具权限 | 按准确范围处理；不盲目换模，不扩大账号或权限 |
| 连接/服务故障 | 判断是否瞬态，核对已执行动作再做有界原模型重试，不作为换模依据 |
| 无法确定类别 | 报告未知，停止自动恢复并取得可执行决定 |

“用 A”默认固定；“同档替换”“找便宜替代”及其他泛化偏好都不足以决定具体模型。用户明确说“A 不可用就用 B”，或给出有限候选顺序时，可按该具体授权执行，不再自行证明同档、不补充候选。每个替代候选最多一次，耗尽即停止；进程重启或上下文转移不重置顺序。保持同 CLI、既有 provider；跨 provider/CLI 需具体授权且已有配置可用，不创建或切换账号。

具体候选授权不抹去用户另给的预算、工具/模态等明确限制。无法核对限制时说明未知并取得对具体选择及未知项的接受；不宣称替代模型能力等价、同价或成本不升。模型身份无法唯一解析时先澄清。

报告原/新模型、故障证据、具体授权和已尝试候选。恢复前核对部分成果、副作用与完整 session，保持任务/项目/权限/限制；无法保持上下文时先接受带背景新委派，不静默新建或盲目重放动作。关联恢复见 [sessions](sessions.md)。
