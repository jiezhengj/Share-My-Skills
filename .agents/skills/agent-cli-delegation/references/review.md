# 评审信息与阶段误判

多轮评审曾把尚未实施/任务未勾选当成设计阻塞，并在已有覆盖后继续寻找假设问题。可在提示中补充当前阶段和结案要求，按任务选用：

> 评审【对象】，当前阶段是【设计/任务编排/实施/验收】；回答【问题】，必要材料/验证是【范围】。发现给出定位、对应要求和当前阶段影响，区分阻塞、建议和未验证项。完成必要覆盖后交结论及证据，不预设通过。

设计阶段未实施本身不证明阻塞；实施验收要查实际成果。提示不必包含全部字段，也不因评审叠加限权。独立进程不证明实际模型不同或 provider 上下文隔离。

# 重复读取与迟迟不结案

重复文件名可能对应新读取区间或交叉验证，结合参数、查询和结果判断；参数不可见时无法据此判停滞。JSON/事件输出或精确原生记录有助于核查，避免全历史扫描。

有新证据时可继续；覆盖完成却迟迟不交付时，指出尚缺项和交付要求，针对性收束。根据任务成本、期限和方法是否变化决定等待、续接或停止，不规定统一预算或次数，也不反复发送没有新信息的“继续审查”。中间 PASS 倾向不能代替最终报告。

对运行中进程发补充指令需要宿主真实输入能力；无此接口时等终态后精确续接。停止进程后核对已执行动作和原生状态，进程退出不保证服务端取消。报告具体未完成项，保持原验收条件。

# 可疑工具与未知根因

出现 Unknown tool、其他项目路径或执行调用方宿主动作的线索时，暂停可疑调用，保留原错误和精确 session，按相关线索检查实际项目、工具请求及可见集合、配置/路由。不猜改工具名或把线索写成已证实 provider 污染；根因未知可继续有依据的诊断。报告尚未成为可核对独立意见时不计完成。

故障只说明本次已知条件，不能保存永久 CLI 黑名单。单项权限受阻如何恢复见[主技能](../SKILL.md#失败假成功与恢复)及相应适配。
