# 阶段评审提示

普通评审沿用 CLI 默认工具、权限、项目配置。以下只补齐任务信息，不添加只读、禁命令或 plan/sandbox 模式；不要求 CLI 修改文件。按任务删去不必要项：

> 目标：评审【对象】，当前处于【设计/任务编排/实施/验收】阶段。
> 范围与必查项：【材料、需要回答的问题、必要验证】。
> 判断：每项发现给出材料定位、对应要求及对当前阶段验收的影响；区分阻塞、非阻塞建议和未验证项。尚未实施或任务未勾选本身不构成设计阶段阻塞；实现验收则核对真实成果。
> 交付：结论、覆盖情况、具体证据、阻塞及未验证项。必查项覆盖完成且没有新增影响验收的证据时提交报告；真实缺口须说明，不预设 PASS，不无限寻找假设问题。

多份独立意见分别启动进程并保存对应原生身份。每份报告独立核查证据；多个 PASS 不证明各报告使用不同模型或 provider 隔离了上下文。

# 增量观察与有限收束

启动前结合材料规模、必要动作、事件能力和用户截止要求，确定本轮观察预算和结束条件；无需编造通用超时秒数。记录最近可观察的材料路径/区间、搜索问题、工具步骤结果和新增证据。重复读取可能是在继续覆盖或交叉验证，不能只按文件名/工具名判停滞；事件缺参数时说明无法判断，必要时查看本轮精确原生记录，避免全历史扫描。

只有新增证据、具体阻塞、恢复决定或终态才向用户更新；单次等待返回、推理变长或仍在运行都不需重复播报。宿主等待采用有界调用并利用完成通知，避免频繁查询同一输出。

预算到达且覆盖/证据无新增时，最多一次针对性收束：指出已覆盖项、仍缺项和交付条件，要求完成剩余必查项后给结论；不引导通过。有真实进展可在本轮明确说明并调整预算，不能靠反复延期维持无界等待。持续输入未验证时不要往运行进程强塞指令；只能在确认终态后按精确会话逐轮续接。需要停止时使用宿主中止能力，核对原生运行状态、部分动作及会话，再决定续接；进程退出不保证服务端取消。

一次收束后仍无进展，停止当前尝试并报告部分结果、具体未完成和限制；不反复发“继续审查/再确认”或把中间倾向当最终报告。终态完整结论、证据与范围都满足要求才算完成。

# 故障候选与未知根因

失败只影响本轮已知条件。例如命令权限受阻仍可进行材料阅读；必需命令验证受阻则该任务未完成。下轮重新预检，不保存永久黑名单或能力排名。随机多个不同 CLI 使用宿主无放回抽样，候选不足说明缺口；候选恰等于数量时全部采用，随机只影响顺序。

出现 Unknown tool 或宿主动作线索，先暂停可疑调用并检查原生项目/session、实际工具请求及可见工具集合、配置/路由证据。保留原错误、已执行动作和未知根因；不要猜替换工具名、认定 provider 污染或擅自切换账号/配置。可疑运行不计有效独立意见，诊断和新委派分别记录。
