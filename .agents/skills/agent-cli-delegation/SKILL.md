# 何时使用与选择 CLI

用户明确要求调用外部 Agent CLI 执行或检查任务时使用本技能；只问安装、版本、参数或故障排查时不启动委派。

用户点名 CLI 时使用指定 CLI。用户一次点名多个 CLI 时分别调用独立外部进程，除非明确要求目标 CLI 的内部 subagent。续接时先由会话关联推导 CLI，用户显式 CLI 用于约束候选；不能用最近成功 CLI 覆盖会话线索。新委派未指定 CLI 时按[会话记录与旧选择兼容](references/sessions.md)读取新旧项目记录，复用已安装的有效最近成功 CLI，否则询问选择。纯查询不启动委派。

“继续刚才”“接着上次某问题”表示续接，不要求人类给 session ID。先从当前对话捕获的身份、项目关联、可访问同项目原生历史依次定位，核对 CLI、项目、完整定位、主题与结果；线索无冲突且唯一时续接，多候选提供摘要供选，没有候选说明未找到，不静默新建。用户指定其他项目时先核对其可访问性和原生项目身份。独立意见、新会话和 fork 使用新关联。续接前核对存在与可观察忙碌状态；精确参数及捕获字段见对应 CLI 参考。

### 首次调用前选择模式

在编写启动命令前，取 CLI 与宿主控制能力的交集：默认单次调用或明确 session 的逐轮续接；持续 stdin、RPC、ACP 或 PTY 只有宿主具备持续写入、输出观察、终止/取消及原生会话核对接口并实际验证后才使用。只有启动与读取接口时降级逐轮调用，不能启动不可控选择器等待人类输入。headless 不是触发条件，模式不扩大授权。随后分别判断输出观察需求和工具权限。

- 需要检索项目文件、核对多个材料、预期多轮工具调用或并行工作的任务，首次调用就采用对应 CLI 的事件/进度输出模式；短小、可预期且无需使用工具的任务可用普通文本。同一任务的普通模式已经长时间无输出时，后续调用直接切换到事件模式，不重复空等路径。
- 事件模式只增加过程可见性，不会批准工具或改变权限。若 headless CLI 无法弹出交互审批，按当前版本的帮助、已有配置和本任务授权范围，预先选好可用权限路径；不要把运行时自动拒绝当成权限预检。
- 每次只增加解决已识别问题所需的选项。出现失败时，依据当前安装版本的 `--help` 和原生事件调整对应选择；不堆叠无关参数、工具限制或配置更改。

# 选择模型

用户明确给模型时先消歧为准确 provider/model/variant，以原生参数传入；默认不授权失败替代。本技能不自主按低成本、强推理或任务智能选型；仅有偏好时按[模型规则](references/models.md)说明不能可靠代选，请用户指定模型，确定前不启动委派。未指定沿用默认或原会话有效模型。记录请求与原生实际模型，未知写 null，不将目录可见说成可调用。保持既有账号与 provider。

# 编写和启动评审任务

提示词写清评审目标、项目或文件范围、要回答的问题和交付格式。只补充完成任务所需的背景；启动独立 CLI 进程不证明 provider 隔离了宿主上下文。若原生事件出现其他项目路径、宿主动作或非本 session 记忆，先核对项目身份及既有 provider 的上下文注入，暂停串会话的后续操作，报告可观察限制。不能通过改账号/provider/配置来制造隔离成功。

普通评审要求返回评审结论，不默认添加“只读”“禁止命令”“禁止工具”或“不得写入”等额外限制，也不为此切换到 plan/sandbox 模式、工具白名单或预配置 Agent。评审任务用 CLI 默认工具和权限启动；用户明确提出零工具尝试或其他硬限制时，先确认目标 CLI 能在本次调用中真正实施该限制，执行时被拒绝不等于没有尝试。

从目标项目根目录启动，让 CLI 找到正确文件和项目配置。保留该项目及当前终端已有的配置、认证和环境变量；不要为让请求通过而替换配置、账号或 provider；模型仅按用户明确选择或具体替代候选顺序及[模型决策规则](references/models.md)调整。不要假定用户预先配置了自定义 Agent；只有用户明确要求，且当前安装版本的帮助和可用 Agent 列表确认该 Agent 存在时才选用。

先查目标 CLI 当前安装版本的 `--help` 和对应适配参考，不跨 CLI 套用参数。长提示或大量文件按该 CLI 支持的文件、stdin 或目录读取方式提供；不要把整份仓库内容拼进命令行参数。

# 判断任务是否完成

退出码或协议中的成功状态只说明 CLI 结束运行。调用方还要检查最终答复是否包含用户要求的结论、证据和格式；没有最终结论的运行不算完成。最终报告说明 CLI、执行方式、续接或新建、请求模型与原生实际模型（未知写 null）、是否替代及依据、实际交付、未完成和未验证事项；不要求用户输入内部 session ID。

按“首次调用前选择模式”确定是否需要进度事件；多轮、多文件、长时间或曾经静默的任务从首次调用开始用事件模式。事件只增加过程可见性，不代表权限隔离。

provider、认证或额度错误只说明这次请求，不据此推断账户整体状态。先核对原生故障、部分动作和会话，再按[模型与恢复决策](references/models.md)处理；不能擅自切换账号或 provider。固定模型失败默认停止换模；只有用户明确给出替代候选及有限顺序时才执行，不自主寻找同档替代、不补充候选。每个替代候选最多一次，耗尽停止；未知故障类别或无法核对用户明确限制时停止并说明。无法保持原上下文先接受带背景新委派，避免重复副作用。把未完成和未知项如实报告。

# 工具请求被拒绝时

先从 CLI 的原生事件确认被拒绝的具体操作、拒绝原因和执行结果。拒绝只说明对应操作未获执行，不自动意味着整个任务失败。

按本次任务范围和当前 CLI 已提供的权限、工具路径继续完成不受影响的工作。若被拒绝的操作仍是完成目标所必需的，依据当前 CLI 支持的权限方式判断能否调整后重试；不要重复已知会被拒绝的相同调用。只有目标确实无法通过当前可用路径完成时，才报告具体未完成项和阻塞原因。

# 修改边界

用户要求评审时，交付评审报告，不额外委派修改。用户明确授权修改时，才让外部 CLI 修改文件，并在提示词中写清修改范围和验收条件。若实际运行出现超出任务的文件变化，先检查再报告。

CLI 专属调用和事件字段见 [agy](references/agy.md)、[pi](references/pi.md)、[OpenCode](references/opencode.md) 和 [CMDc](references/cmdc.md)。
